# Easy GitHub

[English](../../SKILL.md) | 简体中文

这是英文 Skill 的中文译本；入口与行为约定以英文版为维护基线。按用户当前使用的语言沟通，不强制切换英文；保留命令、状态字段、ID、路径和用户内容原值，不翻译机器标识。

让 GitHub 更容易用：AI 交付改动，人审查结果，程序保管版本和协作记录。复用 Git / GitHub，不替代用户的编程工具。

## 先确定工作对象

从当前上下文取得源仓库、已有状态目录、参与者和要做的操作。优先续用已有工作；信息足够就执行，不要求用户学习分支、commit 或 PR 命令。

本 Skill 自带运行脚本。以**包内顶层 SKILL.md 所在目录**为 Skill 根目录（本译本位于其 `references/zh-CN/`），用绝对路径调用 `scripts/`，无需原开发仓库。运行状态、工作目录和证据必须放在 Skill 安装目录之外。依赖 Python 3.11+、Git 和 macOS/Linux；非 ASCII 路径和参数需使用 UTF-8 终端及 locale。真实 CLI、GitHub 是可选接入。

首次使用或需要命令细节时读 [本地工作流](workflow.md)。先查看源仓库当前 HEAD、未提交内容和已有状态；初始化仅导入已提交 HEAD。状态目录位于源仓库之外，可用同级 `<项目名>.handoff`；已有目录先核对归属，不重建或覆盖。状态库有自己的团队版本，不会自动跟随源仓库或远端更新。

## 按用户意图推进

| 用户表达 | 管理动作 |
|---|---|
| “开始做这件事” | `start`，把返回的独立目录交给用户指定的编程工具 |
| “这份改动做好了” | 确认外部写入已停止后 `submit`，固定交付版本 |
| “看看改了什么，能不能一起用” | `review`，展示行为变化、检查结果和需要决定的问题 |
| “另一份改动还没收下，先一起试试” | `review --onto-delivery`，只生成组合预览 |
| “处理这次冲突” | `update`，将新目录及冲突上下文交回外部 AI；修复后重新交付和审查 |
| “把这版送到 GitHub 审查” | 读取 [GitHub 接入](github.md)，核对授权、仓库范围和精确版本后发表 PR / COMMENT |
| “收下这版” | 先明确具体候选与收下位置；本地 `accept` 仅更新隔离状态库，不能声称已更新源项目或远端 |

用户已经在某款工具中编程时，直接交接管理程序返回的目录，不必另开一个模型。只有确需启动外部 CLI 时，读 [编程工具接入](coders.md)，使用随包的 `coders.py`。核心管理程序不写业务代码；冲突修复与测试由外部编程工具完成。

## 保持交接可信

- `owner`、`tool`、`reviewer` 是标签。`reviewer` 表示材料准备给谁，不证明此人已审核；不能另填一个人名来伪造人工批准。
- `--handoff` 是外部工具已停写的声明，不是停写命令。拿到 work ID、attempt、目录和 SHA 后按原值使用，不从名字猜测。新 attempt 不覆盖旧目录；旧目录不能继续交付为新版本。
- 检查必须针对 review 的精确候选 SHA，真实执行后再登记 `check`。AI 的文字自述和 CLI 退出成功都不能代替代码与检查证据。
- `ready` 仅表示候选可以进入审查。接受本地候选需要人对具体 review 的有效确认；新修订、基线变化或开始修复会使旧确认失效。已有授权仍匹配时不重复索要确认。
- `preview_only` 只能预览，不能 `accept`。尚未纳入的依赖候选更新后，需要显式选择新版本并重新修复、审查。依赖已在团队历史中时，按本地工作流准备新候选；旧预览不会自动变成批准。
- 不主动合并 `main`。本包不提供 GitHub merge / APPROVE；用户说“送审”不意味着“收下”。按当前会话授权处理远端写入，不沿用历史实验授权。
- 工具失败如实保留。用户选择换工具时，保留原尝试与交付，并记录新工具的真实执行；不以模拟输出补成成功。

## 对人报告结果

用“正在制作、已交付、需要调整、可审查、已在指定位置收下”等具体状态。先说行为变化和需要人判断的事项，再附必要的 diff、检查证据和 PR 链接。把程序事实、AI 建议和人的决定分开。

操作后回读 `status`；远端操作另回读 PR、head/base 和审查记录。PR 已创建、CI 通过、AI 已审查、人工已批准分别报告。若停止在冲突或工具故障，说明保留了哪份工作及下一步需要的输入。

当前包为原型：本地工作流可用于本地 Git 仓库；GitHub 适配器仅支持 `github.com` 上私有的 `newgit-integration-*` 测试仓库，不支持任意生产仓库。没有图形界面、自动远端同步或正式多人身份权限。Skill 文件可复制安装，已有状态目录包含绝对路径和 worktree 关联，不能随 Skill 打包搬迁。
